Agents can work on plain SSH machines: a human saves an SSH connection through an enrolled node (aliases discovered from the node's config, destination resolved and tested, nothing but an approved normalized snapshot stored), grants it to individual running panes, and the granted pane can run structured commands with bounded incremental output and honest lifecycle, cancel them, and open managed interactive SSH terminals whose input and output ride the ordinary pane tools. The five MCP SSH tools plus get_terminal_execution and the /api/ssh routes carry it; machine credentials cannot configure anything, every generic pane surface asks the same SSH policy, and sharing managed panes is refused in v1. Nothing is ever replayed after an ambiguous disconnect (a lost answer stays `accepted`, reconciliation asks, never restarts), exit 255 is never claimed as a confirmed remote result, and cancellation confirms only the local process stopped. Commands run under a mandatory every-hop policy (strict host checking, no forwarding, no escape characters, no control sockets, key/certificate auth only); credentials, config contents, command text, and output never reach the server, its logs, or the audit trail. The node protocol becomes 16 to carry the nine ssh_* commands, so update the server before the nodes: a lagging agent is held and crosses the bump on the update command.
