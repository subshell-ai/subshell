title: "Linux virtual displays"

A Linux virtual display gives graphical programs in a subshell their own screen without a physical monitor.

## Before you start

Complete [Preview prerequisites and setup](/previews/setup) and confirm that
you have edit access to the subshell to open and control its screen. You need permission to install packages on the node and ownership of its
settings; an administrator configures the server's built-in node.

## Install and configure

Install the dependencies on the Linux machine that runs the subshell, even
when you're viewing it from another device.

1. Use the Linux distribution's package manager to install **Xvfb**, **x11vnc**,
   and **xauth**. Package names vary by distribution; the node needs the
   `Xvfb`, `x11vnc`, and `xauth` commands available on its execution account's
   `PATH`. Install the browser or GUI app you want to use separately.
2. In the server dashboard, open **Settings** → **Nodes**, select that Linux
   machine, and open **Overview**. Turn on **Allow virtual displays**, enable
   **Allow Xvfb + VNC**, and select it as the **Default display provider** if
   you want new subshells to use it automatically.
3. Choose **Recheck** if requirements still show as missing. Once they're ready,
   [launch a subshell with a virtual display](#launch-and-open-a-display).

> [!WARNING]
> The display runs with the subshell's execution account permissions. It isn't a
> sandbox for applications, and its local VNC listener has no separate password.
> Don't enable virtual displays on a host shared with untrusted local OS users,
> and don't publish the listener through a port forward. See
> [Preview security](/concepts/security#preview-security).

## Launch and open a display

1. [Launch a subshell](/guides/launch) on that node with **Virtual display** enabled. Choose
   **Xvfb + VNC** under **Display provider**, or keep **Node default** if it
   selects that provider. The form checks requirements on the selected node,
   which may be different from the device displaying the dashboard. Resolve
   missing requirements and choose **Recheck** before launching.
2. Launch your browser or GUI app from that subshell so it inherits the display
   settings.
3. Use the window icon in the subshell header, then choose **Virtual display**.
   You can see and control the screen in its own workspace tab.

Each subshell saves its selected provider and display size for restarts.
See [Preview prerequisites and setup](/previews/setup#enable-node-features)
for the effects of changing the default or disabling a provider.

You can [save the display choice in a preset](/presets/launch-defaults#save-a-virtual-display-choice).
Review it when changing nodes: if the new node can't provide the display, the
launch form turns the option off and explains why. A pending or failed
requirements check blocks launch until it can be checked or you turn the option off.
