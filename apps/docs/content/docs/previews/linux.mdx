A Linux virtual display gives graphical programs in a subshell their own screen without a physical monitor.

## Before you start

You'll need permission to install packages on the Linux node. Follow
[Preview prerequisites and setup](/previews/setup) for node ownership and view
access requirements.

## Install and configure

Install the dependencies on the Linux machine that runs the subshell, even
when you're viewing it from another device.

1. Use the Linux distribution's package manager to install **Xvfb**, **x11vnc**,
   and **xauth**. Package names vary by distribution; the node needs the
   `Xvfb`, `x11vnc`, and `xauth` commands available on its execution account's
   `PATH`. Install the browser or GUI app you want to use separately.
2. Follow [Enable node features](/previews/setup#enable-node-features) to allow
   virtual displays with **Xvfb + VNC** on this node. Once its requirements are
   ready, launch a subshell as described below.

> [!WARNING]
> The display runs with the subshell's execution account permissions. It isn't a
> sandbox for applications, and its local VNC listener has no separate password.
> Don't enable virtual displays on a host shared with untrusted local OS users,
> and don't publish the listener through a port forward. See
> [Preview security](/concepts/security#preview-security).

## Launch and open a display

1. [Launch a subshell](/guides/launch) on that node with **Virtual display** enabled. Choose
   **Xvfb + VNC** under **Display provider**, or keep **Node default** if it
   selects that provider.
2. Launch your browser or GUI app from that subshell so it inherits the display
   settings.
3. Use the window icon in the subshell header, then choose **Virtual display**.
   You can see and control the screen in its own workspace tab.

## Turn the display on or off later

You don't need a new subshell to change its screen. Use the Web previews &
screens icon in the subshell header and switch **Virtual display** in the
"Open web preview or screen" dialog:

- Turning it on restarts the subshell's process so it starts holding the new
  screen. Its history stays, and agents that support resume continue the
  conversation.
- Turning it off closes the screen right away and frees the memory and CPU it
  used. Apps running on the screen close; the subshell keeps working.
- Changing the size or provider means off, then on again. You can't pick a
  size in the dialog; it always uses the launch default screen size. Where the
  node offers more than one provider, you can choose it under **Display
  provider** before enabling.

Both flips need edit access to the subshell and an online node, and the node's
virtual display settings still apply. After turning a display off, programs
that were already running keep a stale display setting until the subshell next
restarts.
