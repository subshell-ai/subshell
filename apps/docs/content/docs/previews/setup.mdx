Enable the preview features you want on the machine that runs your subshell.

## Before you start

For a graphical machine, follow [Install Subshell Client](/install/desktop-client)
and [Desktop node setup](/nodes/desktop). For a headless machine, follow
[Enroll a node with the CLI](/nodes/enroll), including its installation steps.
You can also use the server's built-in node. On a Mac, either
[Subshell Client](/install/desktop-client) or [Subshell Server](/install/desktop-server)
provides the display helper.

You must own the node to change its preview settings. An administrator configures
the server's built-in node. Install display dependencies on that node, even if
you view it from a different device:

- [Linux virtual displays](/previews/linux) requires Xvfb, x11vnc, xauth, and the
  browser or GUI app you want to run.
- [macOS virtual displays](/previews/macos) requires macOS 14 or later,
  BetterDisplay, local helper consent, and macOS permissions.

## Enable node features

1. In the server dashboard, open **Settings** → **Nodes**, select the machine,
   and open **Overview**.
2. Turn on **Allow web previews**, **Allow virtual displays**, or both,
   depending on the views you need. Each switch has its own effect:

   **Allow web previews** lets people with edit access open web apps and saved
   services. People with view access can watch the browser discovered for their
   subshell. See [Web app previews](/previews/apps) and
   [Browser watching](/previews/browser).

   **Allow virtual displays** lets subshells request a screen for graphical
   apps. Each display uses extra memory and CPU; web previews don't need one.
   Follow [Linux virtual displays](/previews/linux) or
   [macOS virtual displays](/previews/macos) to install dependencies and open a screen.

3. Under **Allow virtual displays**, enable the providers you want this node to
   use and choose a **Default display provider**. Choose **Recheck** after
   resolving missing requirements. Each enabled provider can be selected when
   starting a subshell.

**Xvfb + VNC** requires Linux. **BetterDisplay** requires macOS 14 or later
and the separately enabled helper described in [macOS virtual displays](/previews/macos).
The card checks requirements on the selected node, which may be a different
machine from the one displaying the dashboard.

Changing the default doesn't change existing subshells: their restarts retain
the saved provider. Disabling a provider prevents new allocations and restarts
that need it, while existing displays keep running. Enabling a provider starts
no processes until a subshell requests a display.

The switches work independently and both are off by default. The cards explain
when a feature is disabled or required display programs are missing.

> [!WARNING]
> Turning either switch off blocks new operations without stopping existing
> subshells or immediately closing existing connections. Remove access or end the
> subshell when you need to revoke an existing connection. On a Mac, use
> [Disable helper](/previews/macos#use-and-stop-the-display) to stop capture and
> input immediately.

## Access to views

You need edit access to open an app or control a virtual display. View access
lets you discover views and watch the browser found for that subshell; the app
and screen controls explain why they're unavailable. The header badge counts
only views you can open. If both features are off, the picker explains this and
links to this setup guide; the preview tab also offers **Open node settings**.
