Run Hermes Agent as a Subshell agent.

## Before you start

Install `hermes` using the [vendor instructions](https://hermes-agent.nousresearch.com/docs/getting-started/installation) and authenticate it under the execution account. Enable its harness plugin on the instance and confirm detection on the target node.

## Launch

1. Open the launch dialog and select **Hermes Agent**.
2. Select a preset or configure the supported launch settings.
3. Choose the target node and an existing project directory.
4. Launch and confirm that the CLI opens normally.

The plugin detects `hermes` through PATH and its known locations. `HERMES_PATH` can identify the binary explicitly in the execution environment.

## MCP and session behavior

Hermes uses one-time MCP registration on each execution host. Follow the command shown in the harness MCP setup instructions before using cross-agent tools. The built-in plugin declares MCP and settings capabilities; it does not declare automatic conversation resumption or attention hooks.

Subshell runs the real CLI rather than proxying its provider API. Provider configuration, usage limits, and CLI-specific permissions remain the agent's own settings.

## Register MCP

When the node binary is on PATH, the portable registration is:

```bash
hermes mcp add subshell --command subshell --args mcp
```

Use the host-specific command shown by Subshell if its binary has a different name or path.
