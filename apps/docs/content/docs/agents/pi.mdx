Run pi as a Subshell agent.

## Before you start

Install `pi` using the [vendor instructions](https://pi.dev/docs) and authenticate it under the execution account. Enable its harness plugin on the instance and confirm detection on the target node.

## Launch

1. Open the launch dialog and select **pi**.
2. Select a preset or configure the supported launch settings.
3. Choose the target node and an existing project directory.
4. Launch and confirm that the CLI opens normally.

The plugin detects `pi` through PATH and its known locations. `PI_PATH` can identify the binary explicitly in the execution environment.

## MCP and session behavior

pi needs the community MCP adapter extension and a registered MCP server on each execution host. The built-in plugin declares MCP and settings capabilities; it does not declare automatic conversation resumption or attention hooks.

Subshell runs the real CLI rather than proxying its provider API. Provider configuration, usage limits, and CLI-specific permissions remain the agent's own settings.

## Install the adapter

```bash
pi install npm:pi-mcp-adapter
```

Register the server in `~/.config/mcp/mcp.json` or your project's `.mcp.json`, using the actual executable for that host:

```json
{
  "mcpServers": {
    "subshell": { "command": "subshell", "args": ["mcp"] }
  }
}
```

The MCP child inherits its identity from the launched pane. A normal shell outside Subshell lacks that identity.
