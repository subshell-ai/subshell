This page will cover people: the first registered account becomes the admin; roles are admin/user, assigned from the Users page; an admin can create accounts, reset another user's password (which revokes their sessions — it is a credential rotation, not a session-kill for open WebSockets), and holds instance-wide edit on every subshell — but never delete, re-share, or their own password reset through that door. It will also cover what any signed-in user can see (the roster is instance-wide by design — it is what the sharing picker needs), demotion of the last admin being refused, and the untouchable `system` service account.
