This page will cover server updates: `subshell-server update --check` against the release list, the update that swaps the binary (or `--from` a local file, air-gapped), and the transaction every path shares — a marker written, the old binary kept as `.previous`, the database snapshotted first, and the NEW binary finishing the job at boot: migrations pass and the update is audited, or it restores the snapshot, puts the old binary back, and exits for the service manager to respawn. It will name the trust honestly (the plane downloads and runs code from the release source; empty `SUBSHELL_RELEASE_URL` disables every network path) and the dashboard route an admin cookie can drive.
