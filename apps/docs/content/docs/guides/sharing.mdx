title: "Share a subshell"

Grant other users access to a subshell you own.

## Before you start

Only the owner can change sharing. The recipient needs an account on the same instance. Administrators need a sharing grant to view or control someone else's session. Only the owner can change its shares.

## Grant access

1. In the server dashboard's sidebar, choose **Subshells**. Open the **⋯** menu on your session's card or row and choose **Share…**.
2. In **Search people…**, search by email or name and choose a recipient, or choose **Everyone**.
3. Select **View** or **View + edit** from the access dropdown, then select **Add**. Repeat for other recipients.
4. Review the listed recipients and their access levels, then select **Save**.

**Everyone** means signed-in accounts on the instance, not anonymous visitors.

| Access | What it allows |
| --- | --- |
| View | Read session details, captured output, and the live terminal. |
| Edit | View access plus input, rename, restart, and terminate through the API. |
| Owner | Manage sharing, notification preferences, and permanent deletion. |

For [SSH subshells](/guides/ssh), only the owner can type in the terminal. Recipients can view output even when their share grants edit access.

## What recipients see

> [!warning] Terminal disclosure
> View access exposes terminal output, including any secrets displayed there. Edit access also allows input into the running process, except in SSH subshells, where input remains owner-only.

Attached viewers can see other viewers' device names and terminal dimensions. Notifications remain owner-targeted and aren't added by a sharing grant.

## Revoke access

Remove the relevant grants in the sharing dialog. An agent's pane token can list shared sessions, but it can't inspect or change another user's session through that grant.
