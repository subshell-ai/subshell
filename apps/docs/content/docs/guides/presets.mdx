Save an agent's settings and optional launch defaults in a preset.

## Before you start

The instance must have the harness plugin installed and enabled. Presets belong to your account; installing a plugin is an administrator action.

## Create a preset

1. Open **Presets** and create a preset for the agent.
2. Give it a descriptive name.
3. Set the command options and environment values supported by the harness.
4. Optionally choose a node, working directory, and prompt stack.
5. Save the preset and select it in a launch dialog.

The command preview helps you inspect the resulting configuration. Preset values can include credentials, so use only accounts and keys intended for the agent.

## Launch defaults

The node and working directory identify where the agent will run. A prompt stack supplies initial task text. In the human launch form, these values prefill editable fields.

Editing a preset does not reconfigure an already-running process. Use [Clone and switch presets](/guides/clone) to launch with changed settings.

## Cross-agent communication

Enable the preset's cross-subshell communication option and provide its node and working directory to make it ready for an agent-created helper. MCP reports readiness as `crossCommReady`.

`create_subshell` addresses presets by ID from `list_presets`. Catalog-only entries are not launchable presets. Read [Coordinate agents](/mcp/coordinate).
