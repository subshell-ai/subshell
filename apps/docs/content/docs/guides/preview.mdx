Preview lets you check a website or graphical app alongside the agent building it.

## Enable Preview on the machine

Preview is off by default. In the dashboard sidebar, open **Nodes**, select the
machine running your subshell, and turn on **Allow preview** in its **Preview**
card. The node owner can change this setting; an administrator manages it for
the server's built-in node.

You need edit access to open an app or control a virtual display. View access
lets you discover available views and watch browser frames. Switching Preview
off prevents new operations; it doesn't stop your subshell or immediately close
an existing connection.

## Use Preview from a Mac

You can view and control previews from your Mac in a browser or **Subshell
Client** while the subshell runs on a Linux node. The server's built-in node
also works when the server runs on Linux.

1. Open your server's dashboard on the Mac and
   [enable Preview](#enable-preview-on-the-machine) for the Linux node.
2. Launch your subshell on that node and start the project's dev server there.
3. Follow [Check a website](#check-a-website) to open its app preview. For an
   interactive browser or GUI app, follow
   [Use a virtual display on Linux](#use-a-virtual-display-on-linux).

Install Xvfb, x11vnc, xauth, and the browser on the Linux node when you need a
virtual display. Your Mac doesn't need those programs or its own node to view
that screen.

If the subshell runs directly on macOS, the picker cannot automatically discover
its app ports or browser. Virtual displays require Linux, and Preview does not
capture native Mac app windows. Installing the Linux display programs on a Mac
doesn't add that support.

## Check a website

1. Start your project's dev server inside a subshell. Keep it listening on
   loopback; you don't need to expose its port to your network.
2. Choose **Preview** below the terminal, or use the preview icon in the
   subshell header. A window icon means the subshell has a virtual display;
   otherwise the header uses a globe.
3. In **Open preview**, choose the **App** row for your dev server's port.
4. Check the site in the preview beside the terminal. Try navigation, forms,
   filters, and other interactions, then give your agent specific feedback.

## Arrange and refresh views

Drag preview tabs to keep several apps or screens visible together. Closing a
preview leaves its subshell and other previews running. Hidden previews release
their viewer connections and reopen when you select them again.

The viewer toolbar has refresh and a **More preview actions** menu:

- **Maximize pane** enlarges that workspace pane. **Restore pane** appears
  directly in the toolbar while maximized.
- **Full screen** uses your browser's fullscreen mode. **Exit full screen**
  appears directly in the toolbar while active.
- **Open in browser tab** opens an app preview in a separate browser tab.
- **Close preview** closes the current viewer.

Use the subshell header's preview icon to open another view. When there are
more than six choices, the picker adds search and a scrollable app list with
ports in numeric order. Browser and virtual-display choices stay above that list.

On a phone, previews use the workspace's tab strip without changing your desktop
split layout. The standalone subshell page provides a link for opening an app
in a separate browser tab.

## Use a virtual display on Linux

A virtual display gives GUI programs in a subshell their own screen, without a
physical monitor. Launch a browser there when you need to check browser storage,
login flows, or another graphical app.

1. Install **Xvfb**, **x11vnc**, and **xauth** on the Linux machine running the
   subshell, and enable Preview for that node.
2. When launching a subshell, enable **Virtual display**. The form checks the
   selected machine and keeps the option disabled if requirements are missing.
   Missing programs show a **Set up virtual display** link to this guide.
   After installing the prerequisites, use **Recheck**. The button disappears
   once the requirements pass.
3. Launch your browser or GUI app from that subshell so it inherits the display
   settings. Install the browser on the node separately if it isn't available.
4. Use the window icon in the subshell header, then choose **Virtual display**.
   You can see and control the screen in its own workspace tab.

A virtual display isn't a sandbox for the programs you run. They keep the
execution account's permissions. Don't enable it on a host shared with untrusted
local OS users; see [Preview security](/concepts/security#preview-security).

## Watch browser frames

If a subshell runs Chrome or Chromium with remote debugging enabled on loopback,
the picker can show **Browser**. Select it to watch live frames of that browser.
This view is a screencast; use **Virtual display** when you need keyboard and
pointer control.

A view-only share can watch the browser discovered for that subshell. It cannot
select another browser port on the node. Close the preview tab when you're done.

## Browser compatibility and private links

App previews use an isolated browser document so the website's JavaScript can't
read your dashboard's DOM, storage, or authenticated API responses. Target
cookies stay in the preview's server-side cookie jar. Sites that need browser
storage, service workers, JavaScript-managed cookies, or full browser login
flows should be checked in the node's browser through **Virtual display**.

The proxy preserves your app's paths rather than rewriting HTML or JavaScript.
If a dev server assumes it's hosted at `/`, configure relative asset URLs or a
matching base path. A target's strict content policy can also prevent embedding;
the virtual display gives you the browser's normal website context.

Preview rewrites the target's `Host` to loopback. An app that still refuses it
needs its own host or origin configuration checked; Subshell doesn't rewrite
all application security checks.

Treat a preview URL as a private access link. Anyone who receives it can use it
while its session remains valid, and closing a tab doesn't immediately revoke
a copied link. The server can read forwarded bytes and browser frames. See
[Preview security](/concepts/security#preview-security) for the trust boundaries
and [Architecture](/concepts/architecture#preview-apps-and-screens) for the data path.
