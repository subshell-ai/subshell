---
title: "Preview"
description: "Watch a pane's browser, open its dev servers in your own browser, and view a pane's virtual screen."
---

Preview shows you what a subshell's pane is producing beyond its text: a page a
browser opened, a web server the pane started, or a screen running on the
pane's own virtual display. Everything here reads from your dashboard. Nothing
opens a new port on your machines.

## Before you start

Choose **Preview** below a subshell’s terminal to open the preview picker.
Each app, browser watch, or virtual display opens in its own workspace tab,
split to the right of the terminal.
Drag tabs side by side to see several views together. Each open view also
appears under its subshell in the sidebar; select that entry to return to it.
Opening the same view again focuses its existing tab. Closing a preview leaves
the subshell and its other previews running.

Use the preview icon in the subshell header to open the picker again. The
viewer toolbar keeps refresh and the More menu, which contains **Full screen**,
**Close preview**, and, for apps, **Open in browser tab**. Desktop previews also
have **Maximize pane** in that menu; choose **Restore pane** to return to the
split layout.

When there are more than six choices, use the search field to find a port or
view. Apps appear in port order in a scrollable list; the virtual display and
browser choices stay above it.

A window icon beside a subshell’s name in the sidebar means it has a virtual
display. Click the window icon in its header to open the preview picker, then choose
**Virtual display**. The display opens in a workspace tab and appears beneath the
subshell in the sidebar.

Preview is off until you turn it on for a node. Open the node's page, find the
**Preview** card, and turn on **Allow preview**. Only the node's owner can
change it (an admin can, on the server's own machine). Turning it off stops new
previews; the machine keeps running its panes.

The server’s own node supports Preview too. Its **Allow preview** setting
is managed by an admin on the same Nodes page.

Viewing needs at least view access to the subshell, and opening ports or
screens needs edit access, same as typing into the pane does.

## Open a port the pane opened

When a pane starts a web server, the port shows up in the preview picker. Choose an **App** row and the app appears in a panel inside your
dashboard, proxied to you as if it were local. Choose **Full screen** from the More menu for more
room, or choose **Open in browser tab** from the More menu to use a separate browser tab. Choose a port the pane is
actually listening on. Only ports the node reports can be opened.

## Watch a browser pane

If the pane runs a browser with remote debugging turned on (Chrome and Chromium
use `--remote-debugging-port` for it), the browser's port appears with a
**Browser** row in the picker. Select it and the pane's browser pages stream into the panel as
frames, so you can see what the agent is seeing. Close its preview tab when you're done. Watching is a live look, not a recording.

## Screen, on Linux

A pane launched with the **Virtual display** option gets its own screen on the
node. In the preview picker, choose **Virtual display** and the pane's display appears
in the panel, updating live. This needs the machine to have Xvfb, x11vnc, and
xauth installed. The launch form checks the selected machine before enabling
**Virtual display**. If any programs are missing, the checkbox stays disabled
and names what to install on that machine. Install them, then choose **Recheck**
to enable the option. If the machine can’t be reached, bring its node online and
recheck.

macOS nodes refuse the screen and browser-watch sides of preview the same way.
The Preview section explains that automatic port discovery and browser
watching aren’t supported there. Virtual displays are available on Linux only.

## If an app rejects the proxied host

The preview proxy rewrites the `Host` header to a loopback address with the
pane's port, so dev-server host checks see a local request and normally pass.
An app that still rejects the request is not patched around here, because
silently rewriting headers would hide the app's own security check. Set the
app's `allowedHosts`-style option to accept the address it reports instead.

## On a phone

On a phone, an **App** row opens its own workspace tab too. The More menu lets
you open it in a separate browser tab. On the standalone subshell page, follow
the prepared preview link instead. **Watch browser** still streams frames.
**View screen** works in a workspace preview tab. The standalone subshell page
needs a larger screen for this view.
