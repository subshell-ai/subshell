Install Subshell Server on a machine you control, launch your first agent subshell, and pick it up from your phone and from other machines.

## What you build

Subshell runs real CLI coding agents (Claude Code, OpenCode, Codex, Hermes, pi) in terminal panes on machines you own, and serves those panes from a web app you host yourself. The server is the control plane: its API, its database, and the web UI it serves. A node is any machine that runs agents. A client is a person's interface to the control plane: web, mobile, or desktop.

The result has five properties worth naming before you start:

- **Durable panes.** Every subshell is a tmux session on the machine running it, streamed to the browser with replay on attach. Close the tab and the agent keeps working; any other device you open gets the same pane, live and typeable. The browser cannot tell whether a pane runs on the control-plane host or on an enrolled node, because both stream identically.
- **Many machines, one control plane.** The control plane keeps the UI, the database, the terminal transport, and the decision logic; nodes execute. Commands travel signed, and a node refuses anything that does not verify.
- **Other people, when you say so.** A subshell is private to its owner by default: invisible, not merely forbidden, to everyone else. You can grant view or edit access; deletes, re-shares, and notifications stay with the owner.
- **Agents that coordinate.** Each subshell boots with a small MCP server wired in, so an agent can message its siblings over end-to-end-encrypted channels and can launch or restart other subshells. The control plane stores channel ciphertext it cannot read.
- **Every device.** The web UI adapts to the screen you are on, and a Home Screen install carries notifications. [What Subshell is](/concepts) covers the whole picture, and [How it works](/concepts/how-it-works) the moving parts.

## Before you start

- One machine you control to run the server: Linux (x86-64 or arm64) or macOS (Apple silicon or Intel).
- tmux on that machine, or a way to install it. Every pane runs inside tmux, and nothing launches without it; the setup wizard covers the install.
- An agent CLI helps but is not required. The plain Terminal harness needs nothing installed, so you can start with zero.

## The path

1. **Install and start the server.** [Install on Linux](/get-started/install-linux) or [Install on macOS](/get-started/install-macos): one command downloads the server binary, checks its digest, and runs a setup that ends by printing the address of the setup page.
2. **Create the admin account and launch your first subshell.** [Your first subshell](/get-started/first-subshell) walks the browser wizard: your account, tmux, an agent CLI, and a launch form that leaves you inside a running pane.
3. **Open it from a second device.** [Pick it up from your phone](/get-started/from-phone): sign in from the phone, add the web app to the Home Screen, and get a push when the agent needs you.
4. **Add another machine running agents.** [Add another machine](/get-started/add-a-machine): mint a setup key, run the install command it gives you, and launch subshells there too.
