Finish the browser setup that your install page ended with: create the admin account, add tmux and an agent to the machine, and launch a subshell you can type into.

## Before you start

- A running server and the address it printed, such as `http://localhost:3080/setup`. Everything from here happens in the browser.
- Nothing else. A launch needs only an agent and a folder; a fresh instance has no presets, and none are needed.

## The five wizard screens

Open the `/setup` address. The wizard asks one thing per screen.

1. **Create Your Account.** Fill in the first account; it becomes the instance's administrator. After the first account, sign-up is closed by default, and an admin can reopen it later ([Registration and enrollment](/server/registration)).

   > [!warning] Open the page before anyone else does
   > The setup endpoints are public only until the first account exists, and that is what lets you create it. On a shared network, whoever walks through the page first becomes the admin.

2. **Connect a Network.** This screen is optional, and skipping costs nothing. It offers mesh networks (Tailscale, Headscale, NetBird, Cloudflare Tunnel) so other devices can reach this server on an address that stays private, or published behind an Access gate. Every act here is repeatable under Settings, and [Network plugins](/server/network-plugins) and [Networking and addresses](/server/networking) explain them.

3. **Install tmux.** Every local pane runs inside tmux, and this screen gates the wizard: **Continue** stays disabled until the check finds tmux, so on a machine that already has it the screen costs one press. Where the install command needs no password, such as Homebrew on macOS, the screen offers an **Install** button the server can run. Where it would need `sudo`, the server has no terminal to type the password into, so the screen prints a copyable command to run yourself. Inside the Subshell Server desktop app this screen does not appear, because the app's own assistant already covered tmux.

4. **Add an Agent.** This screen answers one question live: what is on this machine? It lists one row per supported agent CLI (Claude Code, Codex, OpenCode, Hermes Agent, pi), each with a detected or not-found chip. A not-found row carries an **Install** button that runs the vendor's own install command on this machine, and the exact command is spelled out under the button before you press it. If nothing is installed yet, that is fine: a plain **Terminal** pane is always available with nothing to install, and you can add agents later under Settings. See [Agents overview](/agents) and [Install an agent CLI](/agents/install-a-cli).

5. **Start Your First Subshell.** The last screen embeds the launch form, already filled in: the server's own machine (its node row is named "Server" by default), an agent that was detected, and a starting directory. Change any of it or just press **Start**; you leave the wizard inside a running subshell. If you left the wizard early, reopen `/setup` and it resumes at the step you had reached.

## Launching from the dashboard any other time

The same form is the dashboard's create-subshell dialog. It has four fields: **agent**; an optional **preset** (a fresh instance has none, and the wizard drops the row entirely; a presetless launch starts the agent bare); **node** (defaults to the server's own machine until you [enroll others](/nodes)); and **working directory**, an in-app browser of the machine the subshell will start on, so launching on a remote node lets you pick a folder there.

Nothing is remembered between launches: the form starts fresh every time, and the wizard's pre-fill is a first-run convenience. If you launch the same shape daily, that is what [Presets](/use/presets) are for.

## The terminal page

What opens is a live terminal into the pane, not a screenshot and not a log tail. You type, and the agent responds; resize the window and the pane resizes. Close the tab and the agent keeps working: the pane is a tmux session on the machine running it, not a child of your browser, and reopening replays you back into the live screen. This is what lets you start something before dinner and finish it from the couch. [Launch and manage subshells](/use/subshells) covers statuses and restarts, and [Devices](/use/devices) covers who else is watching the same pane.

## Terminate when it is done

Terminate kills the pane's tmux session and the harness with it, revokes that subshell's API token, and leaves the pane's log on disk. The row stays listed as terminated, and restarting it builds a fresh tmux session. The conversation is new unless your agent supports resuming one. Delete removes the row too. As owner, both actions are yours alone; [Share a subshell](/use/sharing) explains what `edit` grants do and do not include.
