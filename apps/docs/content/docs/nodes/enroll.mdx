title: "Enroll a node with the CLI"
description: "Generate a setup key and install the node daemon on another machine."
---

Enroll a machine with your Subshell server using a single-use setup key.

Use this path for a headless machine or terminal-based installation. For most desktop machines, use [Desktop node setup](/nodes/desktop) with Subshell Client.

## Before you start

Sign in to the server with permission to enroll nodes. Use a supported Linux or macOS target with an execution account, tmux, and a reachable server address.

> [!warning] Delegated execution
> Enrollment lets the control plane launch programs under the node's OS account. Use a trusted server and restrict directories where appropriate.

## Install from the server

1. In the server dashboard's sidebar, choose **Settings** → **Nodes**, then select **Add node** at the top of the page.
2. Select an address reachable from the target machine.
3. Generate a setup key.
4. Copy the terminal installation command and run it on the target machine.
5. Choose the machine's display name and whether to install the background service.
6. Confirm that the new node appears online.

The command downloads a compatible node binary from the control plane and runs
`subshell setup`. The name is chosen on the node, not by the setup key. The
generated command sends the download URL to curl through standard input so the
setup key doesn't appear in curl's process arguments.

Treat the copied command as a credential: it still contains the setup key and
may be saved in your shell history. Don't paste it into shared logs or messages.

## Use an existing binary

When a current `subshell` binary is already installed, use the server and key
from the dialog. Check that `subshell --help` lists `SUBSHELL_SETUP_KEY`; update
an older binary before using this form:

```bash
SUBSHELL_SETUP_KEY='nsk_REPLACE_ME' subshell setup --server https://server.example.com
```

Replace the example address and key before running it. The environment input
keeps the key out of command arguments; privileged processes and processes
running as your OS user can still inspect it. The CLI consumes it before
starting child processes. A setup key is single-use and must not be confused
with a rotated node credential.

Setup-key rows remain available to their owner; an unused key's **Setup** action reopens the instructions.
