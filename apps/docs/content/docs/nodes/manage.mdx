Inspect a node's runtime and execution settings.

## Open the node

Select a machine in **Nodes** and review its overview. Check its online state, maintenance state, runtime, and installed harnesses before launching work.

The harness list on a node's page is cached from its last detection, so it may describe an older state. Use **Re-check** to request fresh detection.

## Names and ownership

Node names are display labels. Renaming a node doesn't change its identity, and launch pickers use the current display name.

The server host's node is named **Server** by default. Its internal ID remains `local` even if the administrator chooses another label.

Node owners manage the machine's settings. A share may allow launching there without granting ownership of service, directory, or enrollment controls.

## Service and logs

Where you have management access, review the service and log sections. A node may be online from a terminal process even when no service is installed.

The Service card shows **Start** or **Stop**, and **Install service** or **Uninstall service**, based on the node's reported state. **Restart** is available when a service manager runs the node. Only the node's owner can stop or uninstall its service.

Restart, Stop, and Uninstall service ask for confirmation before making changes. The dialog explains whether subshells may close and whether you'll need access to the machine to bring the node back.

On the machine, use:

```bash
subshell status
subshell service status
```

`status` describes the daemon's recorded state; service status asks the service manager. Avoid `status --probe` during normal inspection because it connects as the node and can displace a running connection.
