title: Glossary
description: The words this product reserves (server, node, client, subshell, pane, preset, workspace, channel, plugin), each in one or two sentences, with a link to the page that goes deep.
---

Three of these words carry the product's weight, and one style rule governs all of them: **no word names two things.** "Server" is the control plane, never a machine that runs agents. "Node" is a machine that runs agents, never an app. "Client" is what a person points at a control plane, never the node daemon. The display labels ("Subshell Server", "Subshell Client", and the control-plane host's node row) sit on top of these words without changing them.

## Terms

**Attention state.** What a pane's harness reports about its current moment: a turn completed, or the agent needs you (a permission prompt, a question). Attention is what lets a notification say "Done, waiting for you" instead of firing on every output line. → [Notifications](/use/notifications)

**Assistant window.** The one window of the Subshell Server desktop app that is allowed to drive the machine: first run, recovery, updating the bundled server, and reset. Everything else the app shows is the server's own page. → [Install the Control Plane](/get-started/install-server), [Reset](/server/reset)

**Channel.** A durable room where subshells talk to each other through the MCP tools. Channels are end-to-end encrypted, so the control plane stores only ciphertext it cannot read. A **nudge** is the narrow exception worth knowing about: it writes one fixed, server-generated line into the recipient's pane to get its attention, and the message itself stays behind `read_channel`. → [Channels](/use/channels)

**Client.** A person's interface to a control plane: the web UI, the mobile companion, the Subshell Client desktop app. A client calls the API; it never runs agents. → [Mobile and Tablet](/get-started/mobile), [Subshell Client as a Node](/nodes/client-as-node)

**Config home.** The directory each binary keeps its settings in: `~/.config/subshell-server` for the control plane (its `config.env` lives here), and `~/.config/subshell` for the node (its `config.json`, the node key's only home). → [Files & Paths](/reference/files-and-paths)

**Control plane (server).** The one process that serves the web UI, holds the database, and makes every decision: what runs, with what credentials, on which machine. In this documentation "server" always means this, never a machine that runs agents. The machine running the control plane is also a node when it hosts panes, and the docs say so. → [What is Subshell](/about/index), [Server overview](/server/index)

**Data directory.** Where the control plane keeps its working state: the pane logs, backups, plugin store, node artifacts, and the update transaction, defaulting to the database file's own directory. The node has its own, under its config home. → [Files & Paths](/reference/files-and-paths)

**Everyone grant.** Two related defaults, one per axis. The control-plane host's node row starts shared with **edit** to every signed-in user, and removing that row's share is how an admin narrows the host down. A subshell's sharing picker can also grant to all signed-in users at once. Both are shares like any other: revocable, and visible to everyone who can see the row. → [Sharing](/use/sharing), [Sharing a Node](/nodes/sharing)

**Harness (harness plugin).** The agent CLI a subshell runs (Claude Code, Codex, OpenCode, Hermes, pi), or, for a plain shell, the terminal plugin. A harness plugin teaches the control plane to drive one of them: the command line to build, the binary to look for, and how to resume. The control plane owns which plugins exist, and one install arms every node. → [Agents overview](/agents/index), [Writing a Harness Plugin](/develop/harness-plugin)

**Maintenance mode.** A per-node flag that says: stay enrolled, keep answering every command, but take no new subshells. Turning it on from either end stops every subshell running on that machine, whoever owns them, and the owner is told by push. It is a routing preference, never a quarantine. → [Maintenance Mode](/nodes/maintenance)

**MCP (`subshell mcp`).** The small stdio MCP server each subshell's harness spawns, one per pane, authenticated as that subshell and nothing else. It is how agents see their siblings, read channels, and launch work. → [The subshell mcp Server](/automation/mcp-server), [MCP Tools](/automation/mcp-tools)

**Network plugin.** A plugin that connects the control-plane host to one network (Tailscale, Headscale, NetBird, Cloudflare Tunnel) and publishes Subshell on it. That is what makes the address you used to discover the instance a trustworthy one to sign in from. The plugin describes the configuration and the host executes it; privileged steps are printed, never run. → [Network plugins](/server/network-plugins)

**Node.** A machine that runs agents: the `subshell` daemon and nothing else, with no UI, no database, and no decision logic of its own. Registering one delegates command execution under its OS user to the control plane, and that delegation is the feature. The node's own key, by contrast, is near-powerless. → [What a Node Is](/nodes/index)

**Node key.** The bearer credential an enrolled node dials its WebSocket with. By design it can do nothing on the REST API: its entire reach is impersonating that one node on its one socket. Rotating it revokes the live connection. → [What a Node Is](/nodes/index), [Managing a Node](/nodes/managing-a-node)

**Pane.** The tmux split a subshell's harness actually runs in. A workspace is an arrangement of panes; each pane holds exactly one subshell, and the browser sees the pane, not the machine. → [Workspaces & Panes](/use/workspaces-panes)

**Preset.** Saved launch settings for one agent: environment variables, command-line flags, a settings blob the plugin understands, and an auto-restart choice. Always optional: a launch needs only an agent and a folder. → [Presets](/use/presets)

**Server.** See [What is Subshell](/about/index). This word names the control plane in these docs, in product names, and in `subshell-server`. The desktop app is "Subshell Server"; the machine a node runs on is not a "server".

**Setup key.** The single-use, 24-hour key (`nsk_…`) that enrolls a node. It stays listed in full on the Setup keys page until it is used, expires, or is revoked, and the server keeps it in plaintext to make that possible. The cost is bounded by the credential being one machine, one use, one day. It is the enrollment credential: minting is gated by an admin toggle, and flipping that toggle off bounds the future without invalidating keys already handed out; deleting them revokes. → [Adding a Node](/nodes/add-node), [Registration & Enrollment](/server/registration-enrollment)

**Share (view / edit).** The two levels a subshell or node owner grants. View is read-only (list, detail, live terminal you cannot type into). Edit adds interacting and managing (typing, rename, restart). Deleting and re-sharing stay with the owner, admins included. On a node, any share, even view, lets the grantee launch their own work there. → [Sharing](/use/sharing), [Sharing a Node](/nodes/sharing)

**Subshell.** One agent session: a real CLI harness running in a tmux pane on a machine you enrolled, private to its owner by default, attachable from any device. Closing the tab detaches; the pane keeps working. → [Subshells](/use/subshells), [Your First Subshell](/get-started/first-subshell)

**System API key.** A long-lived bearer credential an admin mints under Server Settings → API keys for machines that act on the instance as a whole: full access within, refused on admin surfaces, revoked by disabling. It is distinct from the short-lived per-subshell tokens. → [System API Keys](/automation/system-api-keys)

**Trusted origins.** The set of addresses a browser may use to sign in. The list is derived live from the instance's own addresses, the operator's extras (`TRUSTED_ORIGINS`), and any network plugin's published record, never from the request's own `Host`. That exclusion is the point: the list exists to close the DNS-rebinding hole. → [Networking & Addresses](/server/networking)

**`APP_BASE_URL`.** The address the instance calls itself by: the cookie and redirect base, the URL baked into install and enroll flows, and the passkey rpID, because better-auth derives it from here. Changing it moves which host passkeys work on. → [Networking & Addresses](/server/networking)

**Workspace.** A saved arrangement of subshell panes: several agents side by side, stored on the instance, reachable from any device (tiles on a wide screen, tabs on a narrow one). → [Workspaces & Panes](/use/workspaces-panes)
