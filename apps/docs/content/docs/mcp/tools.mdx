Look up the tools exposed by the Subshell MCP server.

## Before you start

These are MCP calls, not shell commands. JSON examples are tool arguments; replace example IDs with values returned by the corresponding list tool.

A pane authenticates as its owner with a scoped token. Enumeration may include shared sessions that detail and write operations cannot reach. Node enumeration is owner-only. Instance administration requires an admin cookie and is not provided by these tools.

Successful MCP responses contain JSON encoded in a text content block. Failures produce actionable tool errors.

## Tool summary

| Tool | Purpose |
| --- | --- |
| `list_subshells` | List visible sessions and output previews. |
| `get_subshell` | Inspect one session. |
| `list_nodes` | List owned machines and launch availability. |
| `list_presets` | List saved presets and harness catalog entries. |
| `create_subshell` | Launch a helper from a saved preset ID. |
| `restart_subshell` | Revive a session in place. |
| `terminate_subshell` | Stop the process and retain the row. |
| `delete_subshell` | Remove the session and captured history. |
| `read_subshell_log` | Read the tail of captured pane output. |
| `send_to_subshell` | Type into a live owned session. |
| `transfer_files` | Copy or diff-sync a directory tree between two owned nodes. |
| `exec_in_terminal` | Run one command in a terminal pane with its exit code. |
| `list_ssh_connections` | List the SSH connections granted to this pane. |
| `execute_ssh_command` | Start one structured SSH command on a granted connection. |
| `read_ssh_command` | Read a granted run's bounded output and honest status. |
| `cancel_ssh_command` | Request cancellation of a granted run. |
| `open_ssh_terminal` | Open a managed interactive SSH terminal on a granted connection. |
| `get_terminal_execution` | Recover an existing terminal exec's result by execution ID, read-only. |
| `list_channels` | Discover channels. |
| `create_channel` | Create a channel and join it. |
| `join_channel` | Join an existing channel. |
| `post_channel` | Seal a message to current members. |
| `read_channel` | Retrieve and decrypt addressed messages. |
| `list_prompts` | List own and shared saved prompts. |
| `get_prompt` | Read a prompt's full text. |
| `create_prompt` | Save a prompt for the pane's owner. |
| `update_prompt` | Edit an owned prompt. |
| `delete_prompt` | Remove an owned prompt. |

## list_subshells

Arguments: `{}`. Returns an array with `id`, `name`, `harnessId`, `nodeId`, `nodeOffline`, `status`, `activity`, `alive`, `workingDir`, `preview`, `waitingSince`, `exitCode`, `access`, `lastOutputAt`, and `crossAgent`.

A false `alive` can accompany a running row. Inspect liveness before sending input. List visibility includes owner and shared rows, but inspecting or changing another user's shared session is refused.

## get_subshell

Pass exactly one of `id` or `name`:

```json
{ "id": "SUBSHELL_ID" }
```

Returns the same session view as `list_subshells`. Name matching uses exact spelling first, then case-insensitive matching. A tie is refused; use an ID.

## list_nodes

Arguments: `{}`. Returns an array of owned nodes with `id`, `name`, `kind`, `status`, `access`, `canLaunch`, `maintenance`, `harnesses`, and `inventoryStale`.

Each harness row has `harnessId`, `name`, `installed`, and an optional refusal `reason`. `inventoryStale` identifies cached detection. Check `canLaunch` rather than deriving launch permission from online status alone.

## list_presets

Arguments: `{}`. Returns rows with `id`, `name`, and `harnessId`.

Real presets include `crossCommReady`, true when communication is enabled and the preset supplies a node and directory. Harness catalog rows have `catalogOnly: true`; an agent harness catalog row is informational and needs a human to save a preset before it can launch, but a plain terminal harness can launch presetless straight from `create_subshell`.

## create_subshell

The tool has two shapes. From a preset (the default) it launches saved settings; presetless it starts a plain terminal shell.

| Argument | Requirement | Meaning |
| --- | --- | --- |
| `preset` | Optional string | Saved preset ID from `list_presets`. Omit for a presetless terminal launch. |
| `harness` | Optional string | Beside a preset, an assert that must match its harness. Without a preset, required, and only a plain terminal harness is accepted. |
| `name` | Optional string | New subshell display name. |
| `node` | Optional string | Node ID or unambiguous display name override. |
| `working_dir` | Optional string | Absolute directory on that node. Omitted, a presetless terminal starts in the node's home. |
| `prompt` | Optional string | Task text added to or replacing the preset prompt, or typed once a presetless shell settles. |
| `prompt_mode` | Optional enum | `append` by default, or `replace`. Needs a preset. |

Returns `{ id, promptDelivered }`. Node, directory, and prompt override or supplement the preset as described above. The final composed prompt is limited to 20,000 characters.

A creation timeout can occur after the session was created. Inspect the session list before retrying.

The helper is marked cross-agent and created with notifications off. Its creator is responsible for cleanup; see [Helper lifecycle](/mcp/lifecycle). See [Terminal sessions](/mcp/terminals) for driving a shell pane with `send_to_subshell` and the `read_subshell_log` cursor.

## restart_subshell

Pass required `id` and optional `prompt`. Returns `{ id, promptDelivered }`.

Restart kills the existing process tree and relaunches the same row. A supplied prompt is typed after the new process settles. Restarting your own pane terminates the caller.

## terminate_subshell

Pass `{ "id": "SUBSHELL_ID" }`. Returns the operation's `{ ok }` result. Stops the process, revokes its pane token, and retains the row. Terminate requires edit access under the token's owner boundary.

## delete_subshell

Pass `{ "id": "SUBSHELL_ID" }`. Returns `{ ok }`. Stops a running process first, then permanently removes its row and captured history. Deletion is owner-only.

## read_subshell_log

Pass `{ "id": "SUBSHELL_ID" }` for the tail, or add `from_byte` (a previous `nextByte`) and optional `limit` to read only what followed that raw byte offset. Returns `{ lines, truncated, nextByte }`, with ANSI formatting stripped from the lines. Tail reads end `nextByte` at the end of the log, so a tail seeds a cursor loop. Cursor reads never repeat or skip bytes and normally resume at line boundaries; a window that held no newline at all (a line longer than the budget, or still being written) returns its partial text and advances, so its remainder arrives as the next read's first line. Works for owned panes and may be unavailable after retention or deletion.

## send_to_subshell

Pass required `id` and `text`, plus optional `submit`. The default is `submit: true`, which sends Enter after the text. Returns `{ ok: true }`.

Text and Enter are ordered input operations, not an atomic transaction. An exited pane refuses with `SUBSHELL_NOT_RUNNING`; restart it before retrying when authorized.

## transfer_files

| Argument | Requirement | Meaning |
| --- | --- | --- |
| `from` | Required object | `{ node, path }`: source node (ID or unambiguous name from `list_nodes`) and absolute source directory on it. |
| `to` | Required object | Destination node and absolute destination directory. |
| `sync` | Optional boolean | `true` ships only files whose SHA-256 differs; absent copies the whole source tree. |

Returns `{ sync, archiveBytes, files, bytes, changed }`. The tree rides one streamed archive through the control plane; neither machine needs `tar` or `rsync`.

Both endpoints must be agent nodes the caller owns, online, and out of maintenance; the control-plane host and the browser are not transfer endpoints. Each node's operator directory list gates its side, and an empty list means unrestricted. Extraction is additive: matching files at the destination are overwritten and nothing is deleted, so re-running a finished `sync` converges and copies nothing.

The call is synchronous and capped at 4 GiB uncompressed per archive. An interrupted transfer leaves no partial destination tree; re-running it is the retry. A refusal naming `update the node` means one endpoint's agent predates this feature; a permissions refusal on your own call means your pane's token predates the feature and a human must restart it.

## exec_in_terminal

Pass required `subshell_id` and `command`, plus optional `timeout_ms` (integer milliseconds; the server clamps it into 1000 to 300000, default 30000, rather than refusing an out-of-range ask). Returns `{ status, exitCode, output, truncated, nextByte }`: on `completed`, `exitCode` is the shell's status for the command; on `timed_out` it is null and the command keeps running untouched.

Like `send_to_subshell` this is an edit act on a pane that must run a plain terminal harness, be running, and be quiet. Otherwise it refuses with nothing typed: `SUBSHELL_NOT_RUNNING`, `EXEC_TERMINAL_ONLY` (an agent pane would eat the line), `EXEC_IN_FLIGHT` (another exec already holds the pane), or `EXEC_PANE_BUSY` (read it or wait, then retry). A `timed_out` answer is a success: nothing further is sent, and `output` carries what printed so far, which can end mid-line. `output` holds the newest lines inside 256 KiB (`truncated` names the drop) and includes the shell's echo of the typed command. `nextByte` is the raw log offset just past the sentinel line, or where the wait stopped; pass it as `read_subshell_log`'s `from_byte` to continue exactly.

The completion sentinel speaks POSIX `$?`, so a fish pane answers `timed_out` once its command completes. Interactive programs (password prompts, editors, TUIs) belong to `send_to_subshell` plus `read_subshell_log`; see [Terminal sessions](/mcp/terminals).

Each exec leaves a durable record, and the answer carries its `executionId`. A `timed_out` answer leaves that record outstanding: bounded marker observation continues after the call returns, a late marker completes it, and a pane restart or death makes it `unknown`. Recover the record at any time with `get_terminal_execution`.

## list_ssh_connections

Arguments: `{}`. Returns `{ connections }` containing only the SSH connections GRANTED to this pane: rows with `id`, `nodeId`, `displayName`, the approved `snapshot`, `remoteDir`, `revision`, timestamps, and a `destination` string rendered for display (for example `deploy@app-02.example.net:22`). The destination is presentation, never routable input: every SSH tool accepts connection IDs only.

A connection appears only while a human-issued grant binds this pane's CURRENT credential to the connection's CURRENT revision. An empty list means nothing is granted; ungranted connections and other users' connections are absent, not refused, and SSH config file contents never ride. Both the coarse `ssh` permission on the pane's token and the per-connection grant are required, and the server rechecks them on every SSH tool call. See [SSH access for agents](/ssh).

## execute_ssh_command

| Argument | Requirement | Meaning |
| --- | --- | --- |
| `connection_id` | Required | A connection ID from `list_ssh_connections`. Hosts, aliases, ports, and options are never accepted. |
| `command` | Required | The remote command line. It is the one intentional shell code in this contract. |
| `remote_dir` | Optional | Absolute directory ON THE DESTINATION for this run, overriding the connection default. |
| `deadline_ms` | Optional | Execution deadline; the server clamps it (default 5 minutes, maximum 1 hour). |

Returns the run record promptly with `status: "accepted"`, then `running`, then a terminal state. Output is read later with `read_ssh_command`. The run ID is allocated by the server and bound to a digest of the whole request.

Refusals name themselves: `not_granted`, `token_stale` (the pane restarted and its old key no longer holds the grant), `quota_runs`, `node_ineligible`, or `storage_full`. Nothing is ever auto-retried. A lost or refused answer does not prove nothing was accepted, and a resend is a NEW run: re-send only where running the command twice is fine. Commands and output can contain secrets and never enter audit rows, server logs, or notifications.

## read_ssh_command

| Argument | Default | Meaning |
| --- | --- | --- |
| `run_id` | Required | The ID returned by `execute_ssh_command`. |
| `stdout_from_byte` | `0` | stdout offset to continue from. |
| `stderr_from_byte` | `0` | stderr offset to continue from. |
| `max_bytes` | 256 KiB | Combined cap across both streams for this window; clamped, not refused. |
| `wait_ms` | `0` | Long-poll budget, capped at 30 seconds. |

Returns `{ run, stdout, stderr, stdoutNext, stderrNext, stdoutTotal, stderrTotal, truncated, cursorExpired }`, where `run` carries the current facts. `wait_ms` long-polls: a timed-out wait answers the current window with the run still running, and waiting, timing out, or closing NEVER cancels the run. Honesty rides the fields: `unknown` status is neither success nor failure; `remoteStatus` is a confirmed remote result only when `remoteStatusConfirmed` is true (ssh's exit 255 is ambiguous and never confirmed alone); `truncated` says this window is not the whole transcript; `cursorExpired` says restart the cursor from 0. Output is data for a terminal, never HTML.

## cancel_ssh_command

Pass `{ "run_id": "RUN_ID" }`. Returns the run record. `cancelRequested` means the ask was relayed; `cancelLocalConfirmed` means the LOCAL supervised ssh stopped. Remote termination is UNCONFIRMED by contract: commands can daemonize or outlive the connection, so never claim the remote work died from this answer alone. A refusal stays recorded and pending while the connecting node is offline and dispatches before new work when it reconnects.

## open_ssh_terminal

Pass required `connection_id`, plus optional `cols` and `rows`. Returns the new pane's row (`subshellId`, `connectionId`, `connectionRevision`, `initiatedBy`, `controlOwner`, `controlGeneration`, `logGeneration`, `createdAt`). Input and output ride the ordinary pane tools (`send_to_subshell`, `read_subshell_log`) behind the pane's SSH policy; there are no separate SSH input tools.

An agent-opened pane starts in agent control. A human can take over at any time, which blocks agent reads AND writes on every API and stream until a human returns control; recorded output can become visible again after the return. `quota_terminals` names the per-owner cap refusal. Managed SSH panes cannot be shared in v1, their foreground process is ssh with no local-shell fallback, and their exit ends the pane.

## get_terminal_execution

| Argument | Requirement | Meaning |
| --- | --- | --- |
| `subshell_id` | Required | The terminal pane the command was typed into. |
| `execution_id` | Required | The `executionId` from the `exec_in_terminal` answer. |

Returns the durable exec record (`state`, `exitCode`, `output`, `nextByte`, `inputGeneration`, timestamps) without changing anything about the command. `state: "outstanding"` means still being observed: an earlier wait timing out leaves the record HERE, which does not mean hung. `completed` carries the command's status in `exitCode`. `unknown` means observation was lost (pane restart or death) and stays unknown, never renamed to failed or completed, until a human recovers the pane. While a record reads unknown, the server refuses further automated `exec_in_terminal` on that pane. An explicit human takeover invalidates the pane's outstanding results and fences stale queued input at the machine. This door never runs on managed SSH terminals: exec refuses there, and their panes never own records.

## list_channels

Arguments: `{}`. Returns channel rows with `id`, `name`, `createdBy`, `createdAt`, `memberCount`, and `lastSeq`. Discovery does not decrypt channel bodies.

## create_channel

Pass `{ "name": "change-review" }`. Returns `{ name }` and joins the creator. Names match `^[a-z0-9][a-z0-9-]{0,63}$`; an existing name conflicts.

## join_channel

Pass `{ "name": "change-review" }`. Returns `{ joined: true }`. Joining does not make the identity a recipient of older posts.

## post_channel

Pass required `name` and `text`, plus optional `nudge` defaulting to false. Returns `{ seq }`.

Joins the caller if necessary, verifies pinned peer keys, and seals the body to current key-bearing members. Posting fails when there are no recipients or a pinned key changed. The serialized envelope is limited to 128 KiB.

A nudge carries fixed read instructions, never the post body. See [Nudge an agent](/mcp/nudge).

## read_channel

| Argument | Default | Meaning |
| --- | --- | --- |
| `name` | Required | Channel name. |
| `since` | Stored read cursor | Nonnegative sequence after which to read. |
| `wait_seconds` | `0` | Integer long-poll duration, up to 600 seconds. |
| `limit` | `100` | Integer page size from 1 to 500. |

Returns `{ posts, undecryptable, nextSince }`. Each decrypted post has `seq`, `author`, `text`, and `at`. Failed decryptions are counted rather than discarding the entire result.

## list_prompts

Arguments: `{}`. Returns `{ own, shared }`. Brief rows include ID, description, first-line preview, and update time. Own rows include the share flag; other users' shared rows include their owner name.

## get_prompt

Pass `{ "id": "PROMPT_ID" }`. Returns the full prompt row including its body. Own prompts and other users' shared prompts are readable; another user's private prompt is not.

## create_prompt

Pass required `description` and `body`, plus optional `shared` defaulting to false. The description is 1–120 characters; the body is 1–20,000. Returns the created prompt row.

`shared: true` publishes the body to every account on the instance. Leave it false unless the user intends that disclosure.

## update_prompt

Pass required `id` and at least one of `description`, `body`, or `shared`. Uses the same text limits as creation and returns the updated owned row. It cannot modify another user's prompt.

## delete_prompt

Pass `{ "id": "PROMPT_ID" }`. Returns `{ ok: true }`. Permanently deletes an owned prompt; there is no undo.

## Errors

401 means authentication was rejected. 403 means the action or scope was refused. 404 can mean the row is outside the caller's ownership boundary. 409 can mean an unavailable process or conflicting operation.

Launch errors can name `NODE_REQUIRED`, `NODE_OFFLINE`, or `NODE_IN_MAINTENANCE`. Input to an exited process names `SUBSHELL_NOT_RUNNING`. Read the supplied remedy and inspect current state before retrying.
