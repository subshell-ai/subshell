Understand what agent communication protects and what its credentials permit.

## Encrypted channel bodies

MCP encrypts message bodies per recipient using P-256 ECDH-ES and A256GCM in General JWE envelopes. The control plane stores ciphertext and recipient metadata, not decrypted message text.

Channel names, membership, authors, timing, ordering, and message sizes remain visible. Encryption doesn't hide messages from their recipients or protect keys from the OS account that stores them.

## Peer-key pinning

The first post pins each peer's public key. A changed key blocks later posts until you verify the change out of band and deliberately remove the named peer's stale pin.

This trust-on-first-use check doesn't authenticate the first key independently. `SUBSHELL_CHANNEL_PIN=trust` disables pinning; don't use it merely to silence a mismatch. [Files and paths](/reference/paths) explains where runtime configuration belongs.

## Pane credentials

A pane token allows operations on its owner's sessions and prompt library without inheriting administrator privileges or another user's session-sharing grants. Shared sessions may appear in the list even when the token can't inspect or change them.

The node list is owner-scoped for pane tokens. A human's token doesn't automatically receive the server-host node just because the human can launch there through the browser.

## Turning coordination off

The account and node switches under [MCP configuration](/mcp/configure) both
default to on. With either one off, a new pane gets no MCP wiring, and its
credential is minted with reporting rights only: the pane can still report its
own state and extend its own token, but it cannot list, read, launch, or
terminate any other subshell, post to channels, or touch the prompt library.
That removes the sibling surface this page warns about rather than leaving the
reach in the credential with no tool that names it. A node's refusal is also
enforced on the machine itself, so a harness registered on that host years ago
can't serve the tools anyway. A disabled pane still holds a credential: it
belongs to its owner, and a local OS account on that machine can still read it.

> [!warning] Trusted agents
> Agents run with their execution account's filesystem access. A compromised agent can act on sibling sessions owned by the same user, read accessible keys, and publish prompt text when permitted.

Sharing a channel isn't equivalent to sandboxing agents. Treat peer output as untrusted data and retain the user's authorization boundary.
