Publish the server through a Cloudflare Tunnel protected by Cloudflare Access.

## Before you start

Create the tunnel, its public hostname, and an Access application in your Cloudflare account. Install `cloudflared` on the server host. The plugin doesn't create or remove your Cloudflare resources.

## Configure the plugin

1. Sign in as an administrator. In the server dashboard's sidebar, open **Settings** → **Networking**, find **Cloudflare Tunnel** under **Networks**, and select **Configure**.
2. Set the hostname, team domain, and Access application's audience value.
3. Supply the tunnel connector token.
4. Choose **Start tunnel**.
5. Open the HTTPS hostname from another device and verify both Access and Subshell sign-in.

The host stores the token in its secret store and supervises the connector. It supplies the token through the connector's environment rather than placing it in argv.

## Access verification

> [!warning] Public hostname
> The tunnel is publicly reachable. Cloudflare Access must protect it before publication; a tunnel token alone isn't an identity gate.

The plugin must confirm that Cloudflare Access protects the tunnel before it publishes your server. If it can't complete that check, publication stops. The server also checks incoming requests against the configured Access policy.

Stopping publication doesn't delete the Cloudflare tunnel or application. Leaving removes the local stored token; manage cloud resources in Cloudflare separately.
