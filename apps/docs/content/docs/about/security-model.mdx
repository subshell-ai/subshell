This page will explain Subshell's security posture in operator terms: it is built for a machine you control or a network you trust (VPN, Tailscale, an SSH tunnel), not for the open internet. It will cover what that means for each thing you can turn on — enrolling a node delegates command execution on that machine to the control plane; sharing a subshell puts its screen, and at `edit` its keystrokes, in front of other signed-in users; channel messages are end-to-end encrypted but their metadata is not. It will also say plainly what is NOT defended: a local OS user on any host in play. The complete threat model lives in the repository, and this page will be its reader's guide rather than a replacement.
