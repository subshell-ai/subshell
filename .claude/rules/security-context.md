**Posture (§0–§1).** A **local / trusted-network service**: a developer's machine or a trusted perimeter (VPN, WireGuard, Tailscale, SSH tunnel), never directly internet-facing. The host's OS-user boundary *is* the trust boundary. NOT defended against: a local OS user; network-level attackers (transport is the operator's deployment; the node ↔ plane link is the exception, app-layer encrypted since protocol 14, §6; the browser link and the downloads are TLS's job, not ours); channel metadata; control-plane compromise (the node signing keypair rules every enrolled node); a malicious admin (no separation of duties); DoS; the harness binaries' supply chain.

## Authentication

Four credential kinds; `apps/server/api/src/api/auth-guard.ts` is the only place credentials become principals. The full inventory and the guard internals (forgery defenses, OIDC plumbing, admin surfaces, WS attach, break-glass, disable plumbing) live in **`apps/server/api/AGENTS.md`, "Authentication"**. The facts every session needs:

- **Session cookie**: HttpOnly, `SameSite=Lax` always; `Secure` only when `APP_BASE_URL` is https (the marking follows the base URL, not `NODE_ENV`). The only actor admin surfaces accept, and the only one that mints an **unbound** WS attach token.
- **System key** (`Bearer subshell_…`): new keys carry versioned explicit grants, checked by each route's `systemPermission`; unannotated guarded routes deny scoped keys. Legacy keys retain their existing non-node access. Derived pane credentials inherit the creator's ceiling, and restart cannot broaden it. Terminal token minting requires `subshells:execute` and binds the ticket to one accessible pane. Machine credentials never manage the instance (`requireAdmin` 403s every non-cookie actor).
- **Subshell token**: 7-day TTL, self-extending while its MCP child runs; revoked **instantly** on terminate/delete. The permission map is a scope gate, not a row fence (§4). Raw REST resolves a pane's token as its **OWNER** with boost and shares off, so a prompt-injected pane can act on the owner's OTHER subshells - the accepted sibling-action posture (§4, §11).
- **Node key**: `/ws/node` and the encrypted discovery envelope only; **no plaintext bearer access on REST** (permanent guard rejection, §5.5); refused while its owner's account is disabled (`4403`); blast radius = impersonating that one node.

Kept posture, in short: the api-key row is lifecycle truth (a key is a subshell principal only when the row, written only by `issueSubshellToken`, matches; self-service api-key endpoints are blocked at the mount); the first registered user becomes admin and the email gate is the **E-mail provider row's** `registration_enabled` (NULL = open only while the instance has no users at all; every OIDC provider answers its own, NULL reads closed); adding a provider is the same trust decision class as installing a plugin, and with `requireLocalEmailVerified: false` the provider's **verified email claim IS the link defense** (§5's inversion); passkeys mint the same session cookie and work only on the configured `APP_BASE_URL` host (rpID); break-glass is a destructive credential rewrite, not a bypass; account disable is one transaction that also kills that person's bearer tokens, live WebSockets, and every node they own; the deliberately public API reads and other conditional-authentication surfaces are inventoried in §3 and `api-surface-auth.test.ts`; WS attach is a 30 s single-use token, scoped tokens bind to one pane and redemption consumes before the bind check (§8); and login backoff (per email, `2^n` s capped at 30) is the only rate limit anywhere.

## Authorization & sharing

- Three axes: **ownership** (a foreign subshell is 404, never 403, from list, detail, log, terminal and workspace-pane paths), **grants** (view/edit, never delete/re-share), and **admin**, which since the 2026-10-09 operator ruling carries **no subshell reach**: the axis resolves roles-free, an admin's view of the pane world is its own panes plus what is shared to it, identical to any account's (reaching another's means becoming that account). Admin remains instance management (users, settings, providers, plugins, network, `local`); status lives in `user_meta`, not the better-auth user row.
- `requireAdmin` 403s every non-cookie actor on instance-management surfaces: user writes, `/api/auth-providers`, `/api/system-keys`, `/api/admin/status`, and the `/api/admin/server` group. Subshell and preset sharing are cookie-only owner actions; node sharing has a separate scoped grant.
- **Per-subshell routes:** the grants switch-off (`allowShares`) is keyed to **a subshell's own key**: it acts only on its owner's OWN subshells, never a foreign or merely-shared one. A **system key is NOT switched off**: it resolves as the `system` service account, limited to panes that account owns or has a sharing grant for, in addition to the key's API permissions (§3).
- **Prompts (`/api/prompts`, spec 2026-09-28):** full CRUD open to bearer actors (the share flip included, by operator ruling: a prompt is plain text, no credential layer; `shared: true` discloses that text to every account the operator already admitted). Foreign row 404 on every path; the list never carries another owner's unshared rows; no audit rows (the presets/channels precedent).
- `GET /api/subshells` passes no actor to the resolver: **bearer callers can enumerate the subshells shared with their owner** (names, status, activity). Disclosure only; acting still 404/403s. KEPT by operator ruling for MCP sibling coordination, PINNED by `subshells-list-visibility.test.ts`; do not tighten the read without moving that test and §3 together.
- `GET /api/nodes` answers a bearer machine token with **its owner's nodes only** (no shares, no admin boost; the MCP `list_nodes` door). Explicitly scoped system keys may also read details, manage ordinary setup keys, and configure owned agent nodes with the route's specific grant. `nodeManagementGuard` refuses legacy keys and pane tokens on those management routes; `loadNodeGate` excludes shares, admin boost, and the local host for bearer callers. Lifecycle, server-address changes, machine trust repair, and recovery setup keys remain cookie-only. The list may disclose the system-owned `local` row without granting management access. See the server's `AGENTS.md` for the read-only display-readiness exception.
- **Instance-wide reads by design** (§3): `GET /api/users` (every account's email, display name, role, disabled state) and `GET /api/settings/public`'s `trustedOrigins` answer signed-in callers and bearer actors, subject to a scoped key's declared grants. They carry no credential and grant nothing on their own.
- `GET /api/admin/status` carries **no secret in any form** (only `usingPlaceholderSecret`, `emergencyLoginActive`); a test scans the serialized body. Treat admin screens as quotable.
- **Sharing** (`PUT /api/subshells/:id/shares`; bearer refused on the shares routes entirely): **view** = list, detail, pane log, read-only live terminal, plus harness subagent view navigation (moving which reported child the parent's terminal shows is navigation, not input; the pane's own key is refused the select door anyway); **edit** adds terminal input, rename, restart, and **terminate** (`POST /:id/terminate` stays live at `edit` at REST/MCP level though the button left the UI). Owner-only forever (never conferred, not held by admins): delete, managing shares, the notification bell. Revoke = clear the grant or an empty `PUT`.
- A share exposes: full pane output (`view`), plus keystroke stream and typing (`edit`); the `viewers` frame discloses every attached device to every viewer including `view`-only grantees. Device labels are re-normalized server-side (`normalizeDeviceLabel`).
- **Push is owner-targeted**: `user_meta.notify_enabled` × per-subshell bell (both on by default, except **OFF for panes an agent opens over MCP**: a create on a pane's own token is stamped `subshells.cross_agent`, born silent, togglable like any bell, and filed under "Cross-agent comms" in the client); sharing never widens who is pushed. The metadata rides third-party relays (§5): Expo posts device token + event kind + opaque subshell id + origin URL to `exp.host`; web-push carries the subshell's **display name** to the browser push service and lock screen; `device_tokens` are plaintext and globally unique; re-enrolling one under another user moves the mailbox.
- **`/ws/live` (§11.14)** is the tree's second authorization path (row→recipients vs viewer→row); the exhaustive diff test between the two is THE control; never delete or weaken it. Role changes and disables drop that user's live sockets; a password reset does not. Broadcasts carry no pane screen and no per-viewer `access` stamp: screens are pulled through the visibility-filtered read; a revocation is asserted only where the audience is addressable exactly, asked otherwise; an unresolvable row is asked about, never asserted away; a viewer who still has access is never told the row is gone.
- **Trust disclosure UI:** foreign-node and shared exposures each show a permanent amber icon plus a one-time dismissible banner. The banner is silenceable per device; **the icon is not**; keep that split. `local` deliberately raises NO node disclosure (`subshell-card.tsx` returns null): every non-admin holds `edit` there via the seeded Everyone grant, so it would read as noise. Don't "fix" it.

## Encrypted channels

- ECDH-ES + A256GCM sealed per recipient (`jose`); the server stores/forwards opaque General JWE and filters reads without decrypting. NOT protected: metadata (names, membership, timing/order, sizes, principals: plaintext on the server), a local OS user (keypairs on the same disk), the bearer tokens.
- TOFU peer-key pinning at `<dataDir>/peers.json` (0600), byte-equality after the first post; strict unless `SUBSHELL_CHANNEL_PIN` is exactly `"trust"`; a legitimate key recovery hard-blocks every peer until that principal's entry is manually deleted.
- Envelopes ≤ 128 KiB, structurally validated on POST; slugs match `^[a-z0-9][a-z0-9-]{0,63}$`; long-poll `wait` clamped to 600 s.
- **Nudge is two-tier** (§7): an idle pane is woken with the server-fixed line SUBMITTED; a mid-turn pane gets the same cue Enter-less (submitting into a busy harness would corrupt its turn). Every nudge line is server-fixed text naming the channel and `read_channel`, never the body; **content stays PULL**; a nudge never fails the post.

## Deliberate non-validation & accepted risks

- **No string length limits on log or subshell free-text fields**; with the qualified half: **labels are capped and normalized**, and a subshell rename enforces 120 chars (§9). **No pagination on small per-user lists** (services, channels). Channel slugs and long-poll waits ARE bounded (Encrypted channels).
- Accepted, do not "fix" (§11): the OS-user trust boundary; `ps`-visible bearer tokens and typed input; control-plane compromise = all nodes; the host filesystem browsable by default; unconstrained admins (a one-click password reset of any other account; passkeys and live sockets survive it); legacy system keys retaining broad access; explicit execution grants carrying the execution account's OS authority; no DoS protection; the in-process post bus (a multi-process deployment loses cross-process wakeups).

## When this changes

Exposing this beyond a trusted network voids §0, and [`docs/security.md` §12](../../docs/security.md) becomes prerequisites, not improvements: HTTPS only with `Secure` cookies and a real `BETTER_AUTH_SECRET`; origin validation and rate limiting on all routes; input length validation and pagination everywhere; set `SUBSHELL_FS_ROOT`; shorten retention and encrypt the volume (and leave debug logging off; paths ride the server log); re-examine the E2EE model (it guards neither metadata nor a host-compromising local user); rotate and review system keys; reconsider node enrollment (node-link encryption shipped, protocol 14, and is not PKI identity: a man-in-the-middle BEFORE pairing still rides enrollment, §12); add sign-in/sign-out audit events; separate admin duties; clear `SUBSHELL_EMERGENCY_PASSWORD`; gate or disable `POST /api/setup/agents/:id/install`; behind a `public-with-gate` plugin the Access guard IS the perimeter; and give the node's loopback dashboard its own credential (or set `SUBSHELL_DASHBOARD=0`) before it stops being loopback-only or lands on a multi-user host.
