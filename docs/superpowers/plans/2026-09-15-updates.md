# Updates — implementation plan

Spec: `docs/superpowers/specs/2026-09-15-updates-design.md`. Read it first;
this plan names the order and the ownership, the spec names the behaviour.
Section numbers below (§) refer to the spec.

Five phases. **A is the foundation and runs alone.** B, C and D depend only
on A and run in parallel in separate worktrees with disjoint file
ownership (listed per phase — do not touch another phase's files; if you
must, stop and say so). E lands last on top of all three.

Every phase: tests beside each new module (`.claude/rules/testing.md`),
then `bun run verify-types && bun run lint:check && bun run test`, plus
`bunx turbo build` for anything under `packages/`, plus `bun run rust:check`
for D. Commit with a pathspec in one command (parallel agents share nothing
in a worktree, but the habit stays). Write a changeset for each of the four
apps you touch — never for an `ignore`d package (`.changeset/config.json`);
protocol/package changes go in the changeset of the app that ships them.
