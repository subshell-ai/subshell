# Dashboard UX review, 2026-10-17

This review covers the server dashboard and the shared node-admin components
it renders. The first pass missed shared runtime facts and some conditional
forms. This follow-up reviews the recurring patterns across routes and their
components; it is not a claim that every possible product state was exercised.

## Findings addressed

| Pattern | Finding and correction | Surfaces |
| --- | --- | --- |
| Read-only facts | Labels and values had similar size and color, and several screens implemented their own pairs. Shared `Fact` now uses smaller muted labels and body-sized foreground values, including monospace values. | Runtime, Status, node details, SSH trust, Networking, clone, enrollment, backup summaries, destination verification, provider removal, command previews |
| Long values | Some review values were truncated or could force a wide layout. Facts wrap complete values; machine facts collapse to one column on narrow screens. | Addresses, paths, fingerprints, commands, SSH summaries, node metadata |
| Radio-dependent fields | Fields below the whole group made their association unclear. The selected option now contains an inset, bordered field panel immediately below its description, outside its clickable label. | SSH authentication, SSH forwarding, Restore source and mode |
| Save availability | Touched fields and unchanged drafts could enable Save. Save now compares the effective draft with saved data, including reverting edits; the disabled Save and its reason carry the pending-change fact, so no separate unsaved-changes sentence is shown. | Sharing, profile, device name, instance name, providers, prompts, prompt stacks, network plugin settings, server addresses |
| Notices and validation | Consequence notices and error styling varied. Shared notices distinguish warnings from failures; backup validation distinguishes missing input from an invalid supplied value. | Sharing, restart, update, supervision, destination verification, backup creation and restore, generated API keys |
| Review information | Destination identity details were hidden behind a disclosure. Destination and copyable fingerprint are now visible at the trust decision. Profile email is presented as a fact instead of an editable-looking field. | SSH verification, account profile |

The [design system](design-system.md) records the shared rules. Creation,
immediate-save switches, and actions that also apply an existing configuration
retain their respective behavior; they are not ordinary draft-save actions.

## Coverage and evidence

Source review covered dashboard routes, their dialogs and editors, and the
shared node-admin fact components. The main review criteria were information
hierarchy, complete values, conditional-field association, validation tone,
Save availability, and narrow-screen layout.

Browser checks used the isolated review backend and Vite frontend, with a
seeded terminal containing a long working-directory path. At both 320px and
1600px, the following route entries had no document-level horizontal overflow
with the available data:

- Subshells, Nodes, the server node detail, Presets, Prompts, Workspaces.
- Account and Preferences.
- Server Settings: General, Users, Auth, API keys, Plugins, Service,
  Networking, Updates, Backups, Status, and Logs.
- The legacy SSH settings entry redirected to Presets as expected.

That is 20 route entries and 19 distinct rendered surfaces. Many lists were
empty in the sandbox; a successful page-width check does not prove every
populated row or dialog fits. Additional browser checks opened the SSH
authentication field panel at both widths and the saved-backup Restore panel.
The SSH dialog had no horizontal overflow, and Restore exposed its associated
region. Runtime and Restore screenshots were visually inspected.

Component tests cover the changed radio association, sharing change/revert
behavior, backup validation and its gold/red tone split, stack editing, address
presentation, enrollment facts, restart and supervision consequence wording,
restore override placement across modes, origins-draft comparison, and the
no-unsaved-message posture. The destination-confirmation e2e spec and its docs
screenshot were retargeted at the always-visible fingerprint. Workspace build,
type checks, lint, and tests are the automated verification for the changes;
these are distinct from browser workflow coverage.

## Limits

This was not a full accessibility certification or an end-to-end exercise of
every role, failure, and integration state. Remote node/key availability,
external identity providers, native key approval, actual server replacement,
live network changes, and populated saved-backup recovery were not exercised
through the review browser. Existing component tests cover some of those
states, but they do not substitute for integration testing.

The native desktop assistant and mobile app were outside this dashboard
review. Shared node-admin changes reach their consumers, but those native
surfaces were not visually checked in this pass.
